# apps Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Собрать бесплатное локальное macOS-приложение apps для просмотра, обновления и удаления CLI-пакетов Homebrew, uv tool и pipx.

**Architecture:** SwiftUI представляет общий список и карточку пакета. Независимые адаптеры читают реестры менеджеров через асинхронный Process runner; модель приложения последовательно выполняет изменения и перечитывает источник.

**Tech Stack:** Swift 6 toolchain, SwiftUI, Foundation, Swift Package Manager, XCTest, shell-скрипт упаковки .app.

**Spec:** docs/superpowers/specs/2026-11-08-cli-manager-design.md

## Global Constraints

- Название приложения — apps.
- Предлагаемая минимальная версия — macOS 14.
- Первая версия предназначена для собственного использования.
- Нет аккаунта, облачного сервера, аналитики и обязательных платных сервисов.
- Команды выполняются от текущего пользователя, без sudo.
- Операции изменения выполняются последовательно.
- Проверки не изменяют реальные установки без отдельного согласования.
- Неизвестные поля метаданных не блокируют просмотр пакета.

## Review Focus

- Одинаковые имена из разных источников должны оставаться разными пакетами (задача 1).
- Большой вывод stdout/stderr не должен блокировать процесс или окно (задача 1).
- Отсутствующий менеджер или неверные данные одного источника не скрывают остальные (задача 2).
- Недоступная проверка обновлений означает неизвестный статус, а не актуальную версию (задача 2).
- Ошибка изменения и повторное нажатие не должны создавать параллельные изменения или ложный успех (задача 3).

## Структура файлов

- `Package.swift`: библиотека AppsCore, приложение Apps и тестовая цель AppsCoreTests.
- `Sources/AppsCore/PackageRecord.swift`: источники, составной ID, метаданные, статус обновлений.
- `Sources/AppsCore/CommandRunner.swift`: асинхронный запуск процесса и результат.
- `Sources/AppsCore/ManagerDiscovery.swift`: поиск исполняемых менеджеров.
- `Sources/AppsCore/PackageManager.swift`: общий протокол адаптеров.
- `Sources/AppsCore/{HomebrewManager,UVManager,PipxManager}.swift`: команды и разбор ответов каждого источника.
- `Sources/Apps/AppModel.swift`: состояние загрузки и операций.
- `Sources/Apps/{AppsApp,ContentView,PackageDetailView}.swift`: окно приложения и детали.
- `Tests/AppsCoreTests/`: тесты runner, парсеров и координатора операций; фикстуры в `Fixtures/`.
- `scripts/build-app.sh`, `Resources/Info.plist`: упаковка локального apps.app.
- `README.md`, `.gitignore`: инструкции и исключения сборки.

## Task 1: Модель пакетов и выполнение команд

**Interfaces:** `PackageRecord: Identifiable, Sendable`; `CommandResult` с exitCode, stdout, stderr; `CommandRunning.run(executable: URL, arguments: [String]) async throws -> CommandResult`. `PackageRecord.ID` включает источник, путь менеджера и имя пакета.

- [ ] Создать минимальный Package.swift и тесты: одинаковые имена в разных источниках имеют разные ID; аргумент с пробелами и shell-символами передаётся буквально; процесс с большим выводом в оба потока завершается; ненулевой exitCode сохраняется.
- [ ] Запустить `swift test`; подтвердить отказ из-за отсутствующих типов/реализации.
- [ ] Реализовать модели и runner, читать оба потока независимо, задать ограничение времени для команд, корректно завершать процесс при отмене.
- [ ] Выполнить `swift test`; ожидать прохождение тестов без изменений установленных пакетов.
- [ ] Сохранить изменения отдельным коммитом после проверки.

## Task 2: Обнаружение и адаптеры менеджеров

**Interfaces:** `PackageManager` предоставляет `list() async throws -> [PackageRecord]`, `checkUpdates() async throws -> [PackageRecord]`, `upgrade(_ package: PackageRecord) async throws -> CommandResult`, `uninstall(_ package: PackageRecord) async throws -> CommandResult`; адаптер получает URL менеджера и `CommandRunning`.

- [ ] Прочитать официальные CLI reference и доступные локальные help для точных флагов и JSON-схем. Получить фикстуры только командами чтения; для отсутствующих источников использовать документированные примеры с указанием происхождения.
- [ ] Написать тесты разбора: пустой список, Homebrew formula/cask, несколько pipx apps в одном venv, uv tools, неверный JSON, отсутствующие необязательные поля и неизвестная доступность обновления. Mock runner проверяет массив аргументов upgrade/uninstall без запуска реальных операций.
- [ ] Запустить `swift test` и подтвердить отказ новых тестов.
- [ ] Реализовать поиск в PATH и стандартных расположениях и три адаптера. Использовать структурированные ответы; при отсутствии нужного формата показывать диагностическое сообщение. Не подменять проверку обновлений установкой.
- [ ] Выполнить `swift test`; все тесты проходят. Проверить список на доступных менеджерах без изменения их установок и сохранить коммит.

## Task 3: Состояние приложения и нативный интерфейс

**Interfaces:** `AppModel` на MainActor публикует packages, sourceStates, selection, searchText, selectedSource, operationState и log; методы `reload() async`, `checkUpdates() async`, `upgradeSelected() async`, `uninstallSelected() async`. Тестируемый координатор в AppsCore не зависит от SwiftUI.

- [ ] Добавить тесты координатора с fake менеджерами: один отказ не скрывает успешные источники, повторный запрос изменения отклоняется, ненулевой exitCode не даёт успеха, после изменения перечитывается только нужный источник.
- [ ] Запустить `swift test`, подтвердить отказ, затем реализовать координатор и AppModel.
- [ ] Создать окно NavigationSplitView: источники, список с поиском и фильтром обновлений, карточка с источником/путями/версиями, действиями и журналом. При неизвестном статусе писать «Не проверено» либо объяснение недоступной проверки.
- [ ] Подключить подтверждение удаления с именем, версией и источником; блокировать действия изменения во время операции, показывать ошибки и результат; сохранять фильтры через UserDefaults.
- [ ] Выполнить `swift test` и `swift build`. Проверить светлую/тёмную тему, пустой список, недоступный источник и длинные имена без реальных удалений. Сохранить коммит.

## Task 4: Локальная сборка приложения

**Interfaces:** `scripts/build-app.sh` создаёт `dist/apps.app` с исполняемым файлом, Info.plist и локальной подписью ad hoc, если codesign доступен.

- [ ] Добавить скрипт упаковки с остановкой при ошибке, Info.plist с названием apps и минимальной версией macOS 14; не включать отладочные файлы в .app.
- [ ] Добавить README с командой сборки, запуском, поддержкой источников и ограничениями; игнорировать `.build/`, `dist/`, временные файлы.
- [ ] Выполнить `swift test`, `swift build -c release` и `scripts/build-app.sh`; проверить plist и подпись, открыть .app и подтвердить запуск, если среда позволяет.
- [ ] Выполнить итоговый просмотр diff и git status, исправить выявленные проблемы, сохранить коммит и передать путь к приложению вместе с фактическими результатами проверок.

## Проверка плана

Все требования спецификации покрыты задачами 1–4. Проверки обновления/удаления выполняются через fake runner; ручная проверка реальных менеджеров ограничена чтением. Неизвестные метаданные и недоступные источники представлены явно. На данный момент код продукта не создан.
